# 你运行在 easyCC 环境里

这是 easyCC 给 AI agent 准备的轻量 Linux 容器（Ubuntu 24.04），不是用户的电脑。它只负责两件事：让你（agent）在一个网络出口受控、和电脑隔离的地方运行；让你读写用户的项目。实时情况（内存、项目在电脑上的路径、能不能连电脑、外网状态）随时运行 `easycc-env` 查看。

## 环境的边界

- **项目是挂载的**：`/workspace`（即 `/projects/<项目>`）直接就是用户电脑上的项目目录。在这里改文件 = 改电脑上的文件，git 也是同一个仓库。
- **资源很少**：通常只有 2–4 GB 内存、几个 CPU 核。内存用光时系统会杀进程，可能连你自己一起杀掉。
- **没有管理员权限**：用户 `dev`，没有 sudo，不能 apt install。
- **网络受控**：所有外网都经 easyCC 的代理出口，直连被防火墙挡住；联网检查没通过时外网是关着的。不要尝试绕开代理、改代理或防火墙、清掉 HTTP(S)_PROXY 环境变量。
- **自带工具**：git、Node.js 22、Python 3、build-essential、ripgrep、jq、curl、tmux，以及一个浏览器（Firefox 或 Chrome，按环境设置；`cbox-browser <网址>` 打开，用户在 easyCC 的「浏览器桌面」里能看到）。

## 什么在这里做，什么到电脑上做

**适合在环境里做**：读代码、改代码、搜索、git 操作（提交、分支、diff）、写文档，跑很轻的命令（单文件格式化、小脚本、`node -e` / `python3 -c` 验证一小段逻辑）。

**不要在环境里做**，改到用户电脑上做：

- 安装项目依赖：`npm/pnpm/yarn install`、`pip install -r`、`uv sync`、`bundle install`、`cargo build`、`go mod download` 等。
- 构建、跑完整测试、启动开发服务器、数据库、Docker，以及 Xcode / Android / Flutter 等平台工具链。
- 安装任何语言运行时或 SDK。

原因有三个。第一，内存小，重任务容易被杀。第二，项目目录在电脑上：在这里装依赖，会把 Linux 版的二进制（`node_modules`、`.venv`、`target/` 等）写进用户项目，电脑上就用不了了；反过来，电脑上装好的依赖在这里也跑不起来。第三，项目最终在用户电脑上运行，运行时和依赖本来就应该装在那里。

## 到电脑上执行：`ssh host`

用户在 easyCC 里打开「访问本机 → 允许 SSH 控制本机」后，`ssh host` 直接登录用户电脑。需要在电脑上安装、构建、测试、运行时，用 `easycc-host` 技能（或按 `easycc-env` 给出的命令格式），在项目的电脑路径下执行。

- 电脑是用户的主力机器：只做和当前任务直接相关的事。删除文件、改系统设置、装全局软件（如 `brew install`、全局 npm 包）之前先问用户。
- `ssh host` 连不上时，不要退回到在环境里硬装运行时。告诉用户两个办法：
  1. 在 easyCC 环境后台「总览 → 访问本机」点「一键授权访问本机」，再打开「允许 SSH 控制本机」。Mac 还要在「系统设置 → 通用 → 共享」里打开「远程登录」。
  2. 或者把要执行的命令整理好，让用户自己在电脑终端里执行，再把结果贴回来。

## 端口和网页

- 环境访问电脑：授权「访问本机」后，`host.internal:端口` 就是电脑上的 `localhost:端口`。电脑上跑的开发服务器，在环境里用 `curl http://host.internal:3000` 或 `cbox-browser http://host.internal:3000` 访问。
- 需要用户在网页上登录、授权（比如 CLI 的登录链接），用 `cbox-browser <网址>` 在环境浏览器里打开，再请用户到 easyCC 的「浏览器桌面」里完成。

## 连不上外网时

先运行 `easycc-env` 看「外网」一行。如果是联网检查没通过（例如代理不通、出口地区变了），外网是 easyCC 故意关掉的，用来保护用户的账号。把原因告诉用户，请他在 easyCC 环境后台的「联网检查」里处理，不要自己想办法绕过。
